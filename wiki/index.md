# The Pascal RE wiki

A field manual for reverse engineering 16-bit DOS binaries built with Borland Pascal. It grows every time somebody reads a binary. See `README.md` for how to check it, and `CONTEXT.md` for the vocabulary.

## Observations

* [A zero byte where the original has something else](observations/zero-byte-difference/observation.md) - the rule inverts by artefact, and using the wrong one is destructive in both directions
* [The same bytes answer to two different addresses](observations/two-names-one-address/observation.md) - segment:offset is a many-to-one name; convert to linear before believing duplication or a gap
* [The rebuild nearly matches, and the last bytes name their causes](observations/near-match-diff/observation.md) - each residual diff pattern fingerprints one source construct or compiler switch; read it, do not tune
* [The file is bigger than its load image](observations/file-bigger-than-image/observation.md) - the tail past the MZ image is data for another reader; the measured cause is Borland debug info, decoded whole by tddump.py
* [The operand it evaluates first is the one written second](observations/operands-evaluate-backwards/observation.md) - Borland computes the RIGHT operand first and parks it, so the spare register names the term written second; four bytes per expression, and the intuition points the other way
* [The original contains code that does nothing, and you have to put it back](observations/the-original-does-nothing/observation.md) - a loop of self-assignments, a test whose branches match, an addition of zero; a reconstruction never invents them and no declaration-driven tool can see them
* [The total balances and the layout is still wrong](observations/balanced-total-hides-order/observation.md) - two errors of the same size in opposite directions leave every total exact; a per-reference shift map sees what a sum cannot, and a bounded run of one shift is a misplaced block
* [A var parameter shares one load where a pointer cannot](observations/var-parameter-shares-one-load/observation.md) - a var parameter's address IS its frame slot, so the compiler holds it across a run of adjacent statements that name it and needs no hidden slot; a pointer must be re-loaded per mention and the nested `with` that would share a load costs four bytes of frame, so the two constraints have no common solution -- when six spellings of a statement have each failed, question the DECLARATION it depends on
* [Pair operands by position once the lengths agree](observations/pair-operands-by-position/observation.md) - once every routine in a segment is the right length, two builds pair operand-for-operand by code offset and a wall of differing bytes becomes a short list of shifts; read it from the lowest address up, and validate the instrument by reintroducing a defect before trusting a clean report from it
* [Every routine is present, aligned, and in the wrong place](observations/length-sequence-names-the-order/observation.md) - definition order is segment order and a content-locating coverage walk cannot see it; the sequence of routine lengths is the same multiset permuted, and two units wrong by equal amounts in opposite directions read as 100.0%
* [The main program is a list of every unit's entry-point offsets](observations/program-segment-names-the-offsets/observation.md) - segment 1000 calls every unit by absolute offset, so comparing it byte for byte checks every entry point at once and catches what a walk, a size check and a data-image compare all miss; prologue offsets then localise it, and separate two errors that cancel
* [Every instrument reads clean and the screen is blank](observations/name-resolution-is-invisible/observation.md) - a shadowing local measures identical on every static instrument and produces a program that does nothing; no byte compare can see WHICH object a name resolved to, so the watched run is the detector, not the confirmation
* [A hardcoded address copied from the original is right by coincidence](observations/transcribe-the-meaning-not-the-constant/observation.md) - transcribe hand assembler verbatim, except the addresses inside it; a literal displacement is byte-perfect and reads the wrong memory, and the byte-level score REWARDS the bug
* [One runtime call serves div and mod, and the call cannot tell you which](observations/one-helper-two-operators/observation.md) - the helper returns the quotient in one register pair and the remainder in the other, so the operator lives in the two moves that may or may not follow; and checking the value against its consumer's range is a free second reading
* [A sixteen-bit address computation that emits thirty-two-bit code](observations/word-plus-integer-is-longint/observation.md) - the sum of a Word and an Integer is a LongInt, so the most natural pixel-address line compiles to CWD, a register pair and an ADC; a widening instruction where no width is needed is the tell
* [Read a shared unit in the binary that uses least of it](observations/smallest-consumer-reads-the-unit/observation.md) - the smart linker leaves one unit at N different sizes; the smallest is sixty-four bytes and four items instead of two thousand and forty, and every correction found there pays out in all N. Two one-byte tells settle near versus far
* [Two bytes the compiler cannot emit](observations/instruction-the-compiler-never-emits/observation.md) - a probe that spells the source every plausible way and matches the original in NONE of them has identified hand assembler, in code where every positive tell is absent
* [Code past the initialisation section came from an object file](observations/code-after-the-init-section/observation.md) - the position proves it, not the instructions; and an object is linked whole, so a dead routine in one ships where a dead Pascal routine is smart-linked away
* [The line table advances one line per instruction](observations/line-table-reveals-asm/observation.md) - a dense stretch in the debug info's line table marks an inline asm block, no disassembly needed
* [Readable text sits between the routines](observations/text-between-routines/observation.md) - the gaps hold length-prefixed string literals; walk them and read the program's behaviour before its code
* [Every declared routine matches, and the rebuild still behaves differently](observations/verifier-blind-to-absence/observation.md) - a byte check driven by declarations cannot see a routine nobody declared; align every byte instead
* [The same routine sits mid-unit in one binary and at a segment head in another](observations/one-routine-two-units/observation.md) - where it sits says whether the original shared a unit or shared source text, and a shared unit changes the call
* [A compare tool's number is plausible, and it is wrong](observations/plausible-and-wrong/observation.md) - the density gate and the location strategy both belong to the artefact; set for the wrong one they shorten or displace the measurement without failing
* [Two implementations of one comparison differ by two bytes](observations/mixed-run-of-differences/observation.md) - a run of differing bytes can hold two reasons, so the rule must return how many bytes it accounts for, not whether
* [A believable percentage about a position nowhere near the thing](observations/search-loosened-drifts/observation.md) - search under the strict rule and re-measure under the loose one; a positional rule and a sliced buffer need one coordinate frame
* [Two tools measure one thing and one number is lower](observations/two-tools-one-number/observation.md) - two classes of permitted difference that overlap make the sum double-count; measure the intersection and the discrepancy becomes arithmetic
* [One block reports a large shift while every block around it is exact](observations/block-past-the-end/observation.md) - our segment is shorter than the original's, so the block was never comparable; clipping and comparing past the end are both confidently wrong
* [Every element read costs fourteen bytes and goes through the frame twice](observations/nested-static-link/observation.md) - a static link at [BP+4]: the routine is nested and its data belongs to the enclosing routine, which fixes the source's shape
* [The same source builds twice and the files do not hash the same](observations/rebuild-hashes-differ/observation.md) - a .TPU and an .OBJ carry a build timestamp; the executable does not, so it is the only honest unit of a reproducibility check
* [A tool reports a shortfall and blames something plausible for it](observations/drifted-second-copy/observation.md) - two copies of one measurement drifted, and the drift MANUFACTURED a finding phrased as an observation about the code
* [A locator keyed on one spelling of a prologue reads working code as absent](observations/one-encoding-of-a-prologue/observation.md) - `MOV BP,SP` has two encodings and a scan listing one gave two wrong answers, neither an error: no code at all under one release, and code starting at the second routine under another
* [An exemption list is where a check goes to die](observations/exemption-that-cannot-fail/observation.md) - four exemptions carried false reasons and the fifth could not fail; an exemption is a claim, and a claim about two texts can be diffed
* [Near or far is decided by the surrounding unit](observations/far-comes-from-the-unit/observation.md) - the procedure header does not say which it is, so one include can carry the same text into a unit that publishes it and one that does not
* [A total quietly drops a component and stays plausible](observations/absence-reads-as-zero/observation.md) - a pattern matching nothing because the tool is gone is indistinguishable from a tool that measured nothing
* [A script breaks and nothing in the import graph explains it](observations/config-is-a-dependency/observation.md) - a config, another program, a generated file and a directory layout are all dependencies, and none of them is an import
* [The code is full of INT 34h and you conclude something about the coprocessor](observations/n-and-e-are-different/observation.md) - $N decides whether 80x87 instructions exist, $E decides how they ship; a trap is evidence of the second and of nothing else
* [The frame is bigger than your locals account for](observations/frame-size-counts-locals/observation.md) - the ENTER operand measures the source's var block, and whether there is an ENTER at all names the unit's $G switch; one instruction, read two ways
* [The call site names the parameter list](observations/call-site-names-the-parameters/observation.md) - RET n gives the parameter block's size and the caller's pushes partition it, in declaration order, with the widening idioms naming the types; it also finds parameters the callee never reads, which must still be transcribed
* [A runtime `DEC` before an array subscript names the array's bounds](observations/subscript-fold-names-the-bounds/observation.md) - the low bound is folded into the displacement for a bare variable and evaluated at runtime for an expression, so four bytes of addressing read a declaration the binary otherwise does not carry
* [A loop counter the binary assigns to proves nothing about where it lives](observations/loop-variable-assigned-is-not-local/observation.md) - RETRACTED: Turbo Pascal does NOT refuse the assignment for a local counter, so the old proof was unsound; what survives is the source shape, `N := Limit` rather than Exit or a flag
* [Borland Pascal emits one instruction per operator, so `+ 3 + 5` is not `+ 8`](observations/one-operation-per-operator/observation.md) - adjacent integer constants are NOT folded, 1 and 2 become INC/DEC, and `- 0` still costs SUB AX,0; the frame is identical either way, so this is the defect class every prologue check passes
* [Inc(v, n) and v := v + n compile to different code](observations/inc-is-not-an-assignment/observation.md) - Inc modifies memory in place and the assignment loads, adds and stores back, six bytes apart on a LongInt; the ADD's operand direction names which was written, and a spill around a call names the operand order
* [An odd local offset means data alignment was off](observations/alignment-switch-pads-the-frame/observation.md) - $A is per unit and leaves a signature nothing else does; two one-byte gaps at different depths in one frame is alignment, not a missing variable
* [The data segment is laid out in reverse of the uses clause](observations/dgroup-order-reverses-uses/observation.md) - code segments follow the clause forwards and DGROUP runs backwards down it; until the order is right, every absolute data reference carries a wrong displacement and correct code measures as wrong
* [A pointer costs four bytes where the array cost four thousand](observations/pointer-where-the-array-was/observation.md) - a buffer put on the heap where the original declared it inline leaves DGROUP short by the whole array; no code-level instrument can see it, and the gaps between the addresses your own comments have accumulated price every declaration and find it
* [The comment already said so, and the code did not do it](observations/the-comment-already-said-so/observation.md) - a note recording an address, a frame size or a stride is a transcription of something measured, while the code beside it is an interpretation written earlier; grepping your own comments for claims the code does not honour found five defects in one day
* [A prologue scan finds every routine, and one thing that is not a routine](observations/prologue-scan-endorses-data/observation.md) - the false candidate is cheap; the second measurement that then agrees with it is not, so withhold everything about a candidate nothing calls
* [The byte walk reports the same number either way](observations/operation-count-names-the-shape/observation.md) - a rebuild that computes the same value more times than the original is invisible to a coverage walk and exact to a count of x87 sites, because a trap count measures source SHAPE and needs neither build's layout
* [The decoder names two 16-bit opcodes with their 32-bit mnemonics](observations/decoder-widens-two-mnemonics/observation.md) - capstone in CS_MODE_16 prints 0x98 as `cwde` and 0x99 as `cdq` where a 16-bit decode is CBW and CWD; only the mnemonic is wrong, so the listing reads as plausible 386 code and copying it adds an operand-size prefix
* [The direction bit tells hand assembler from compiled Pascal](observations/direction-bit-names-basm/observation.md) - Borland's built-in assembler emits every register-to-register op in the store direction and the code generator is mixed, so the ratio over a routine separates the two where an ENTER-framed prologue makes them look identical
* [A loop limit that is not a constant is a frame slot you must not declare](observations/loop-limit-is-a-temporary/observation.md) - a `for` loop's upper bound is evaluated once into a stack temporary and read every iteration, which is indistinguishable from a declared local; transcribe it as one and you get both it and the compiler's
* [A harness can never match the original's runtime call addresses](observations/harness-cannot-match-runtime-addresses/observation.md) - a harness puts a different main program ahead of the runtime, so every far call into it differs in its segment word by construction; measure the deltas before treating a cluster of them as reconstruction work
* [A typed constant nothing reads is invisible to every comparison that follows an instruction](observations/dead-data-has-no-witness/observation.md) - decoders, fixup maps and operand pairings are blind to dead data by construction; code exact and data long means a declaration nothing reads, code exact and data short means one you have not made
* [A filler declaration records what you have not looked at, not what is not there](observations/filler-is-not-a-finding/observation.md) - three fillers in one reconstruction turned out to BE fields, each of them sitting immediately beside something the new version added; re-read every filler adjacent to anything new
* [An initialiser that changes no byte means the declaration is at the wrong address](observations/initialiser-that-changes-nothing/observation.md) - set a typed constant to the value the original's image holds and rebuild; nothing moving is the finding, and within a unit the ORDER of declarations is as measurable as their sizes
* [A named constant that only some of its uses go through is worse than no constant at all](observations/constant-only-half-applied/observation.md) - change it and the literals stay behind, reading as a second unrelated defect in another part of the unit; grep the OLD VALUE before rebuilding
* [When two declarations both fit the bytes, build both -- the compiler decides](observations/compiler-arbitrates-two-readings/observation.md) - two adjacent immediate stores are one 32-bit assignment or two 16-bit ones, and only the use sites separate them; peephole behaviour like a special-cased zero store is not derivable from a disassembly
* [A tool that is wrong is useless; a tool that BECOMES right is worth re-asking every open question](observations/instruments-have-an-order/observation.md) - instruments have a dependency order and a downstream one reports noise that looks like findings; when an upstream verdict changes, re-run everything before doing new work
* [Writing a routine is not enough to emit it](observations/unreferenced-routine-is-dropped/observation.md) - Borland drops what nothing reaches, so a stub reached only through a published pointer leaves a hole exactly where it belongs and looks like a transcription not yet done
* [A one-byte difference between two builds is two different findings](observations/one-byte-gap-is-ambiguous/observation.md) - a ModRM displacement whose field moved, or the low half of a data reference whose high byte did not; the signed reading invents a record-shrink at dozens of sites, and congruence modulo 256 against the word buckets is the test
* [A hello-world names the compiler that built a stranger](observations/minimal-program-fingerprints-the-compiler/observation.md) - compile a four-line program with each candidate and search the unknown for its runtime head with relocations masked; the ones NOT found are the useful half, and a binary you already understand is the control
