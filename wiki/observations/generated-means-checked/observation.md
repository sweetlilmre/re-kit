# A file is generated only while something compares it against its generator

A generated source file carries a banner saying so: *generated by `emit.py` -- do not edit*. That banner is not a fact about the file. It is a claim about the relationship between two files, and a relationship is the one thing no build, no byte comparison and no artefact check ever measures. Each of those reads one file and answers a question about that file. **Nothing in the ordinary apparatus asks whether the generator still produces what is committed.**

So the file goes on saying it is generated long after it stopped being.

## How it happens, and nobody is careless

The prose at the top of a generated file is real documentation, and eventually somebody improves it -- strips reverse-engineering apparatus out of it, rewords a paragraph, fixes a citation. They edit the file, because that is where the text is. Updating the generator's embedded copy of the same text is a second act, in a different language, in a different directory, and it is easy to not do.

Both halves of that are reasonable. The result is a tree where every file is correct, every generator is correct, and only the relationship between them is wrong.

**The damage is latent and it detonates on someone else's turn.** The generator is the one thing that will overwrite those edits without asking, and it runs next when somebody regenerates for an unrelated reason -- possibly months later, possibly to answer a question about a different file entirely. On the target below the divergence was found only because a generator was run to settle an argument about line endings.

## Why every other instrument is blind, and it is structural

On one corpus the divergence was **comment-only in all seven files, with the data identical in every one**. That is not a lucky accident, it is the common case: the text at the top of a generated file is the part a person wants to edit, and it is also the part a compiler discards.

Follow that through and the whole measuring apparatus is disqualified by construction:

- The **build** passes, because comments change no compiled byte.
- **Whole-binary identity** against the original holds, because the bytes are the same bytes.
- Every **code-identity** check -- segment comparison, coverage walk, unit sizes, data image -- passes for the same reason.
- The **stripped-copy gate**, on a target that keeps a derived documentation copy, checks the copy against the source and never the source against what produced it.

Nothing was wrong with the tree. What was wrong is that two things claimed to be the same file and no instrument compared them. A green report from every instrument you own is not evidence when none of them is pointed at the question.

## The instrument

`--check` on the generator: regenerate into a temporary directory, compare each output against the committed copy, write nothing.

**Classify each difference, because the two kinds carry very different weight.**

- **Comments only, data identical.** The two disagree about wording. Nothing downstream changes; it is a merge question, and either side may be the right one to keep.
- **The data differs.** Stop. A byte-identical build is resting on committed copies the generator no longer produces, and regenerating over them would move real bytes. That is the case worth refusing on.

**Enumerate the generator's OUTPUTS, not its entry points.** On the target below one file was produced as the second half of another emitter and had no function of its own, so a check that walked the emitters would have passed over exactly the file that had diverged most. Name the outputs in a list and let the check read the list.

## Blind spot

**A comparison says the two disagree; it does not say which one is right.** That is a judgement, and it belongs to whoever knows why the edit was made. Answering it needs the history: on the target below the hand edits were a closed ticket's deliverable, so the tree was right and both generators were adjusted to match it. The opposite verdict is just as available and the check cannot choose.

**A generator that reads its own config can diverge through the DATA rather than the code.** One of the two generators on that target held its offsets, lengths and prose in a TOML file, and its divergence was in the TOML -- the program was fine. A check that regenerates covers this and a code review does not.

**A check on one generator says nothing about the others.** Both generators on that target had the same defect from the same cause, and only one of them acquired a `--check`; the other is the kit's, and changing it is a separate act. Finding the shape in one place is a reason to go looking, not a reason to feel finished.

## The same shape, three times in one day

The banner is one instance of a wider defect: **an unexamined claim about a relationship decays into cover for whatever the relationship has become.** Two more from the same session, both on the same target:

- A table of assets declared *hand-made, nothing generates these* -- 28 rows, of which **25 were false**. One file was fully explained elsewhere in the repository and the table went on calling it unidentified. The other 24 had a generator until it was archived, after which they became files nothing produced, which is indistinguishable from somebody's work to any tool that only looks at the tree.
- A retirement record saying a deleted tool was *superseded by* its successor, having verified two of that tool's outputs and stopped. Twenty-four others lost their producer the same day. They stayed on disk, so nothing read as missing.

In all three the artefacts themselves were fine and the claim about them was stale. **"Nothing generates this", "generated by X", and "superseded by X" are all assertions that something was compared. Each one needs the comparison to be a command somebody can run.**

## Cost

Regenerating into a temporary directory and comparing, which is a few dozen lines and runs in seconds. Testing it costs three deliberate breakages -- a hand-edited comment, one changed data value, a missing file -- and each has a different classification to check.

## Example

A 1994 DOS demo reconstruction, 1 Sep 2026. A documentation ticket had hand-edited all seven generated Pascal includes to strip apparatus, and neither generator was updated -- so running either would have reverted that closed ticket, seven files at once, and the only thing preventing it was nobody happening to run one. Comment-only in all seven, data identical in all seven, verified by comparing with comments stripped; the build stayed byte-identical and all ten byte-exact artefact rows went on holding throughout. Found by accident, weeks later, when a generator was run to answer a question about line endings. The repair also exposed three defects no build could have seen: one file carried its *generated by* banner twice, another read `1 faces the loader reads` where the hand edit had quietly corrected the pluralisation, and a third had a duplicated paragraph left by an earlier split.
